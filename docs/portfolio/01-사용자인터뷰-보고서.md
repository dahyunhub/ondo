# 사용자 인터뷰 보고서 — 온도(ONDO)

> 현직 유치원·어린이집 교사 대상 인터뷰로 MVP 기능 우선순위와 핵심 가치를 검증한다.
> (작성일: 2026-07-04 · 현직 교사 3명 인터뷰 완료, 목표 3~5명)

| Q1 | 서류 작성에서 **가장 반복적인** 업무는 무엇인가요? | 일지/관찰평가가 진짜 병목인가 |

## 4. 핵심 인사이트 → 기능 결정

1. **"관찰평가"가 원 유형·서류 환경과 무관한 공통 병목**
   → 서류 부담은 **원마다 편차가 크다**(P1·P2 모두 "지금 원은 간소화"). 그런데 **관찰평가는 세 명 모두** 부담·우선순위로 지목. 특히 P2는 *"교사가 관찰한 내용으로 발달적 특성을 자동 인식해주면 부담이 줄겠다"*.
   → *결정: MVP 출력물을 A(개인 관찰평가) / B(하루 일지)로 분리하고, 관찰평가를 1급 기능으로. 누리과정·발달 특성 연계를 프롬프트에 내장.*

2. **범용 GPT의 약점 3가지 = 서비스의 존재 이유**
   - *놀이가 한정적*(P3) → 도메인 프롬프트로 놀이 확장 + **또래 상호작용 · 교사 지원**을 자동 포함.
   - *스타일이 획일적*(P2, "아이·일지마다 다르게 쓰고 싶다") → **아이별 누적 메모를 맥락으로** 넣어 개별화.
   - *맥락을 매번 다시 넣어야 함* → 메모가 **아이 페이지에 자동 축적**돼 재입력 불필요.
   → *결정: `resources/prompts/` 도메인 프롬프트 + 출력 검증(OutputValidator) + 아이별 메모를 근거로 묶는 오케스트레이션.*

3. **"기록 재조회"는 실재하는 페인 — 아이별 타임라인의 근거**
   → P1: 아이의 **시간에 따른 변화**(알레르기·병원·성향)를 알 수 없다. P2: 키즈노트 **검색 한계**로 결국 새로 씀, **주차·생활주제별 나만의 기록** 요구.
   → *결정: 메모를 문서가 아니라 **아이 단위 타임라인**으로 축적. (향후: 기간/주제별 필터·검색 강화 — 백로그)*

4. **3항목 구조는 수용되나, "적는 것"조차 더 줄여야 한다**
   → P1 "무난", 하지만 P2는 **표시·체크(동그라미, 소극/적극)** 로 더 빠르게 + **전이시간·식사·낮잠** 등 만2세 맥락 항목을 요청. 만2세는 주의집중 10분 미만이라 서술형 관찰이 어렵다.
   → *결정: 현재 3칸(놀이·의사소통·태도)은 유지. **연령별 입력 프리셋과 탭·체크형 빠른 입력**을 개선 백로그로 등록.*

5. **확장 여지: 안전일지·등하원일지·상담기록지·적응일지**
   → 일지·관찰평가 외에도 반복 서류가 다수 언급(P1 안전일지, P2 등하원·상담·적응일지). 같은 "메모→AI 초안" 구조를 문서 유형만 바꿔 확장 가능.

## 5. 인용구 (자소서·면접용)

> "GPT한테 놀이상황을 주고 월–금 작성해달라 하면 **놀이가 한정적**일 때가 있어요. 상호작용 과정이나 **교사의 지원**이 함께 써지면 좋겠어요." — P3

> "그대로 쓰기엔 부족해서 **50%만 도움받고** 제 생각으로 수정해요. **아이마다 스타일을 다르게** 쓰고 싶은데 비슷하게 나와서, 아직 100% 의존할 단계는 아니에요." — P2 (만2세·어린이집)

> "교사가 관찰한 내용을 바탕으로 **발달적 특성을 자동으로 인식**해준다면 관찰평가 부담이 줄 것 같아요." — P2

> "원아조사서를 5세 입학 때만 받아서, 이 아이가 그 뒤로 **어떻게 달라졌는지(알레르기·병원·성향·좋아하는 놀이)를 알 수가 없어요.**" — P1 (만4세·유치원)
